# Visual testing guide

## Why tests are section-level

The post-wedding page is long. A single full-page screenshot shrinks into an unreadable strip during review and can hide serious defects such as cropped people, unreadable labels, broken image integration, or excessive section spacing.

The Playwright suite therefore captures each semantic block separately at desktop and mobile widths.

## Covered blocks

| Snapshot name | Selector |
| --- | --- |
| `hero` | `.after-hero` |
| `timer` | `.after-timer` |
| `story` | `.after-story` |
| `day` | `.after-day` |
| `gallery` | `.after-gallery` |
| `honeymoon` | `.after-honeymoon` |
| `thanks` | `.after-thanks` |

With two viewports, this produces fourteen post-wedding baselines in:

```txt
tests/e2e/after-wedding.spec.ts-snapshots/
```

Do not consolidate them into full-page screenshots.

## Deterministic setup

The test URL freezes time:

```txt
/?now=2026-10-14T08%3A52%3A03%2B03%3A00
```

The expected timer starts with `49` days. Tests also:

- force lazy images to load;
- wait for every image to complete;
- wait for fonts;
- disable animation during comparison;
- request reduced motion;
- verify the memory page is the default branch, legacy `afterWedding` links still work, and the invitation remains available with `?invitation`;
- verify both branches are selected before application scripts load.

## Commands

Run the existing baselines:

```sh
npm run test:e2e
```

Regenerate all baselines after an intentional visual change:

```sh
npm run test:e2e:update
```

Limit regeneration while iterating:

```sh
npm run test:e2e:update -- --grep desktop
npm run test:e2e:update -- --grep mobile
```

After updating, always run the suite again without `--update-snapshots`.

## Review workflow

1. Make the code or asset change.
2. Run `npm run typecheck` and `npm run build`.
3. Regenerate only the relevant desktop/mobile snapshots while iterating.
4. Open every changed PNG at real resolution.
5. Compare it with the neighboring design language and the previous baseline when available.
6. Fix defects rather than approving them into the baseline.
7. Run `npm run test:e2e` without update mode.

## What to inspect

Hero:

- title wrapping and hierarchy;
- clean transparent edges;
- couple scale and section-bottom alignment;
- no pink or green halo.

Timer:

- all four values remain on one row;
- labels and dividers are readable;
- frozen values are `49 20 32 03`.

Story:

- the full 3:2 image is visible;
- all five people are present;
- neither the groom nor side guests are cut;
- the table and centerpiece remain readable;
- mobile puts the illustration before the copy.

Day:

- four cards on desktop and one column on mobile;
- the sequence is wedding ransom, ceremony, guest tour / couple's photo session, then restaurant;
- the wedding ransom film link fits inside the first card and has a visible keyboard focus;
- icons are centered and crisp;
- connector decorations do not overlap text.

Gallery:

- the note about pending professional photos and video is readable;
- the guest photo album and wedding ransom film are clearly labeled;
- links sit side by side on desktop and stack on mobile;
- keyboard focus is visible and link content fits without clipping.

Honeymoon:

- South Korea and Gangnam Style copy remains short and readable;
- copy and the trip film link sit side by side on desktop and stack on mobile;
- only the trip film is shared; the private photo album is absent;
- the link and icon remain within the card at mobile widths.

Thanks:

- heading and text remain centered and readable;
- button contrast and focus treatment are sufficient;
- the rounded section is not clipped.

## Baseline discipline

- A passing update command only means files were written; it does not mean the design is correct.
- Never update baselines merely to make a failure disappear.
- If one section changes, unexplained changes in other sections are regressions until proven otherwise.
- Do not commit Playwright run artifacts under `test-results/` or `playwright-report/`.
- Keep platform-specific baseline naming generated by Playwright unless the project intentionally adopts a cross-platform rendering strategy.
